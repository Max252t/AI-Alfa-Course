# Задание агенту: запустить и проверить бота «Альфа-Наставник»

Ты запускаешь на этом устройстве Telegram-бота из репозитория проекта и проверяешь его в работе. Код написан и покрыт тестами, но сборка через Docker, загрузка данных и сквозной прогон ещё ни разу не выполнялись. Скорее всего, ты найдёшь ошибки. Исправляй их в коде.

## Правила

- Секреты (токен бота, ключи LLM, пароли) не печатай в чат и не коммить. Токен бота и ключи спрашивай у пользователя, не придумывай.
- Выгрузка кейса (`data/raw/*.backup`, `Описание данных.docx`) и `.env` не должны попасть в git. Перед каждым коммитом смотри `git status`.
- Комментарии в коде не пиши. Коммиты в стиле Conventional Commits, без указания соавторов. Работай в новой ветке `fix/first-run`, в `main` не коммить.
- Не меняй поведение, описанное в README, без необходимости. Если ошибка в логике, а не в запуске, опиши её в отчёте и исправь минимально.
- Если нужно действие, которое можешь сделать только человек (установить Docker Desktop, выдать токен, перенести файл выгрузки), остановись и попроси.

## Шаг 1. Окружение

1. Проверь `git --version`, `docker --version`, `docker compose version`. Если Docker нет, попроси пользователя установить его и остановись.
2. Получи код проекта (клонируй репозиторий или используй уже скопированную папку) и перейди на ветку `main`.
3. Убедись, что файл `alfa_course_hackathon.backup` лежит в `data/raw/`. В git его нет, пользователь переносит его вручную. Если файла нет, попроси.
4. LLM по умолчанию Ollama. Проверь, что Ollama запущена (`http://localhost:11434`) и модель `qwen2.5:7b` скачана (`ollama pull qwen2.5:7b`). Если Ollama нет, спроси пользователя, какой провайдер использовать (`openai`, `gigachat`, `yandex`) и откуда взять ключ.

## Шаг 2. Конфигурация

```bash
cp env.example .env
```

В `.env` задай:
- `TELEGRAM_BOT_TOKEN` — токен от пользователя;
- `POSTGRES_PASSWORD` и тот же пароль в `DATABASE_URL`;
- `ID_HASH_SALT` — любая случайная строка;
- параметры LLM для выбранного провайдера.

На Linux `host.docker.internal` в compose уже сопоставлен через `extra_hosts`. Если Ollama недоступна из контейнера, проверь это отдельно.

## Шаг 3. Запуск

```bash
docker compose up --build -d db backend
docker compose logs -f backend
```

Дождись, пока `GET http://127.0.0.1:8000/health` вернёт `{"status":"ok"}`. Потом загрузи данные (займёт несколько минут, скачивается модель эмбеддингов около 1 ГБ):

```bash
docker compose --profile etl run --rm etl
```

Ожидаемый итог в конце вывода: `materials=… interactions=… chunks=…` и `done`. В выгрузке около 2000 материалов и порядка 40 000 записей активности и оценок; точные числа после фильтрации зависят от статусов. Затем:

```bash
docker compose up -d bot
docker compose logs -f bot
```

Типичные места поломки (проверь в первую очередь):
- сборка образа backend: установка `postgresql-client-17` из репозитория PGDG;
- миграция `0001_init`: расширение `vector`, вычисляемая колонка `tsv`, индекс GIN;
- ETL: `pg_restore` в БД `alfa_source`, имена колонок в SQL-запросах, типы citext, кодировка;
- поиск (`backend/app/services/rag.py`): приведение `CAST(:qv AS vector)`, передача параметров через asyncpg;
- первая загрузка модели эмбеддингов (кэш `hfcache`).

## Шаг 4. Проверка

Сначала без бота, через API:

```bash
curl "http://127.0.0.1:8000/materials/search?q=как%20выбрать%20налоговый%20режим"
curl http://127.0.0.1:8000/stats
```

Ожидается список материалов со скорами и ненулевые счётчики. Затем попроси пользователя написать боту в Telegram (или сам отправь запросы через `POST /chat` с произвольным `tg_id`) и пройди три сценария:

1. «Как выбрать налоговый режим для кофейни?» — ответ по базе с источниками, до двух рекомендаций, кнопки 👍 / 👎 / «Ещё по теме» / «Напомнить изучить», уточняющий вопрос «ИП или ООО». Проверь, что платный материал показан только с краткой пользой и ссылкой.
2. «Напомни заплатить налог» → вопросы про режим и форму → часовой пояс → подтверждение. Затем «Напоминай каждый вторник продолжить курс» → «Сделай раз в две недели» → «Отключи». Проверь `/reminders`.
3. «Как платить меньше?» — уточнение кнопками. «Как получить визу в Китай?» — честный отказ. «Перескажи платный урок» — без содержания урока, только польза и ссылка.

Проверка срабатывания напоминания (вне тихих часов 22:00–09:00 по часовому поясу пользователя):

```bash
docker compose exec db psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "UPDATE reminders SET next_run_at = now() WHERE active;"
```

Сообщение должно прийти в течение минуты.

Затем оценка качества:

```bash
docker compose run --rm etl python -m eval.eval_rag
docker compose run --rm etl python -m eval.eval_recommender
docker compose run --rm etl python -m eval.eval_reminders
```

По таблице порогов из `eval_rag` предложи значение `RELEVANCE_THRESHOLD` и поставь его в `.env`, если оно заметно лучше 0.6. Утечек платного контента должно быть 0.

## Шаг 5. Отчёт

Верни пользователю:

- что запустилось, что нет, с текстом ошибок (без секретов);
- список исправлений (коммиты в `fix/first-run`);
- результаты трёх сценариев: что сработало, что нет, с примерами ответов бота;
- метрики из `eval_*`;
- рекомендованный `RELEVANCE_THRESHOLD`;
- замеченные проблемы вне запуска: странные ответы, пустые источники, неверные ссылки (проверь шаблоны `URL_TEMPLATES` в `etl/mapping.py`), подозрительные налоговые сроки.

Критерий готовности: все сервисы работают, ETL завершён, три сценария проходят, `eval_reminders` даёт 100% по календарю и не менее 90% по расписаниям, платный контент не утекает.
